# M4 Devices (simulated) + digital twin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Claim a simulated module for a plant, sync raw readings through a cloud twin that converts them and sends instructions back, and show live module status in the app.

**Architecture:** Two Edge Functions (`device-claim`, `device-sync`, `verify_jwt = false`, module secret hashed) write five new owner-only tables. Pure shared modules in `supabase/functions/_shared/` hold the module rules (`watering.ts`, also run by the Node simulator in `sim/`) and the twin maths (`twin.ts`). The app reads the `devices` row (latest values) through TanStack Query with polling, computes one status sentence per plant, and adds two setup steps.

**Tech Stack:** Supabase (Postgres, RLS, pgTAP, Deno Edge Functions, no npm deps), Node 22 (runs `.ts` natively, zero deps), Expo SDK 58 / Expo Router / TanStack Query / react-native-svg, Jest + RNTL.

**Spec:** `docs/superpowers/specs/2026-11-18-m4-devices-design.md` (read it with this plan; § numbers below refer to it).

## Global Constraints

- Branch `m4-devices` (from `main`); one commit per task; push; PR to `main` at the end. Never commit `supabase/functions/.env`, `apps/mobile/.env.local` or `sim/.devices/`.
- No new dependencies (app, functions or simulator). Functions: plain `fetch`, `_shared` helpers (`readJsonBody`, `json`, `jsonError`, `rest`, `Deps`, `envDeps`).
- Function errors are `{ "error": "<our message>" }` only; log one line per request: request id, device id, outcome. Never log secrets, hashes or bodies.
- Safety limits never relax: ≤ 40 ml/dose, ≤ 150 ml/rolling 24 h, never pump with the float low, stop after 2 doses with no moisture rise. Compiled worst-case pump rate 4.0 ml/s → `maxDosePumpMs = 10_000`, `maxDayPumpMs = 37_500`.
- Every new table: RLS on, owner-only, cross-user pgTAP test; `service_role` grants explicit and asserted in `service_role_grants.test.sql`.
- Schema only via `supabase/migrations/`, then `npm run db:types`.
- App: `src/ui` + theme tokens only, no raw colours, no emoji, no font-scale caps; primary actions in `BottomBar`; loading per `LoadingGroup` / `Skeleton*` / `FadeIn`; unknown values show "—"; press handlers synchronous (`void doAsync()`).
- Copy is fixed by spec §8 where quoted; status lines are dot-joined, no final period; banners are full sentences.
- TDD: failing test first, smallest change to pass. Ponytail: least code that fully works.
- Checks before done: `npm test`, `npm run typecheck`, `npm run lint`, `npm run db:test`, `npm run fn:test`, `npm run sim:test`.

## Review Focus

1. **One bad item in an offline buffer** (clock unset → `ts` in 1970, a raw value of 5000, unknown event type): the sync must store the valid items and skip the bad ones, never 400 the whole request, or the module's buffer is stuck forever. Test in Task 5.
2. **A retried sync** (module timed out after the server stored it): no duplicate readings/events, `ml` not double counted, acks still succeed. Test in Task 5.
3. **Degenerate calibration** (`soil_air_raw = soil_wet_raw`, `tank_full_raw = tank_empty_raw`): conversions return `null`, never `NaN`/`Infinity`, and instructions still come out inside the limits. Test in Task 3.
4. **Claimed module that hasn't sent a reading yet** (`reading_ts` null): status is Quiet "Waiting for its first check-in", never "Doing well". Test in Task 7.
5. **A code typed by hand** (`k7p4-qm2x 9rtd`): normalised and accepted; characters outside the alphabet (`O`, `I`, `0`, `1`) → 400. Test in Task 4.

### Task 2: Module rules — `watering.ts` (safety-critical; lead implements or reviews with Opus)

**Files:**
- Create: `supabase/functions/_shared/watering.ts`, `supabase/functions/_shared/watering_test.ts`

**Interfaces:**
- Produces (no Deno APIs, no imports: the Node simulator imports this file):
```ts
export const LIMITS = {
  worstPumpMlPerS: 4.0, maxDosePumpMs: 10_000, maxDayPumpMs: 37_500,
  minRiseRaw: 30,          // soil raw must drop at least this much after a dose to count as a rise
  refillRiseRaw: 150,      // tank raw rise between wakes that counts as a refill
  soilRawMin: 500, soilRawMax: 3500,   // plausible soil sensor range
  lowBatteryMv: 3650,
  readS: [300, 3600] as const, syncS: [900, 21_600] as const,
  backoffS: [3600, 7200, 14_400, 21_600] as const,
};
export type Fault = 'no_moisture_rise' | 'sensor_out_of_range' | null;
export interface Instructions { water_when_soil_raw_above: number; pump_ms: number; min_minutes_between_doses: number; read_interval_s: number; sync_interval_s: number }
export const DEFAULT_INSTRUCTIONS: Instructions = { water_when_soil_raw_above: 2400, pump_ms: 5000, min_minutes_between_doses: 120, read_interval_s: 900, sync_interval_s: 3600 };
export interface RawReading { ts: string; soil_raw: number; tank_raw: number; float_low: boolean; battery_mv: number; charging: boolean }
export type EventType = 'watered' | 'refill_detected' | 'tank_low' | 'battery_low' | 'boot' | 'fault';
export interface DeviceEvent { ts: string; type: EventType; pump_ms?: number; code?: Exclude<Fault, null> }
export interface ModuleState {
  instructions: Instructions;
  doses: { at: number; pump_ms: number }[];     // epoch ms, pruned to the last 24 h
  pendingRise: { soilRawBefore: number } | null; // set by a dose, checked at the next wake
  noRiseCount: number;
  fault: Fault;
  last: { tank_raw: number; float_low: boolean; battery_mv: number } | null;
  failedSyncs: number;
}
export function newState(): ModuleState;                        // first start after a claim: DEFAULT_INSTRUCTIONS, empty budget
export function freshState(now: number): ModuleState;          // saved state lost/unreadable (never for a new module): doses = [{ at: now, pump_ms: maxDayPumpMs }] (budget used up)
export function clampInstructions(i: Instructions): Instructions; // pump_ms ≤ maxDosePumpMs, intervals into readS/syncS, minutes ≥ 0
export function wake(state: ModuleState, r: RawReading, now: number): { state: ModuleState; pumpMs: number; events: DeviceEvent[]; syncNow: boolean };
export function clearFault(state: ModuleState): ModuleState;     // fault null, noRiseCount 0 (only for no_moisture_rise; sensor fault untouched)
export function afterSync(state: ModuleState, ok: boolean, instructions?: Instructions): ModuleState; // ok: failedSyncs 0, instructions clamped+stored; else failedSyncs+1
export function nextSyncDelayS(state: ModuleState): number;     // failedSyncs 0 → instructions.sync_interval_s; else backoffS[min(n-1, 3)]
```
`wake` order: (1) resolve `pendingRise` (rise if `soil_raw ≤ before − minRiseRaw` → `noRiseCount = 0`, else `noRiseCount + 1`; at 2 → `fault = 'no_moisture_rise'` + fault event); (2) sensor range: outside `[soilRawMin, soilRawMax]` → `fault = 'sensor_out_of_range'` (event when newly raised); back in range clears only that fault; (3) events from `last`: float false→true `tank_low`, tank raw rise ≥ `refillRiseRaw` `refill_detected`, battery crossing below `lowBatteryMv` `battery_low`; (4) decide dose; (5) `syncNow` = any event emitted. Pump time = `min(instructions.pump_ms, maxDosePumpMs, maxDayPumpMs − sum(doses in last 24 h))`; no dose if ≤ 0.

  - `never pumps while the float reads low` (dry soil, `float_low: true`) → `pumpMs === 0`.
  - `caps a dose at 10 s whatever the instructions say` (`pump_ms: 60_000` stored unclamped) → `pumpMs === 10_000`.

  - `a rise resets the no-rise count`.

export interface Calibration { soil_air_raw: number; soil_wet_raw: number; tank_empty_raw: number; tank_full_raw: number; tank_full_ml: number; pump_ml_per_s: number }

Body: top level must be exactly the keys `firmware_version` (string 1–32), `fault` (null or a fault code), `readings` (array ≤ 200), `events` (array ≤ 100), `acked` (array ≤ 20 of uuid strings); otherwise 400. **Items** that fail validation (unknown keys, ints out of range, `ts` outside [now − 14 d, now + 5 min], unknown type, `watered` without `pump_ms` 1–60 000, `fault` without a valid `code`) are **skipped**, not fatal; count them as `skipped` in the log line.
  3. `GET devices?secret_hash=eq.<hash>&select=id,reading_ts,battery_pct,soil_air_raw,soil_wet_raw,tank_empty_raw,tank_full_raw,tank_full_ml,pump_ml_per_s` → none → 410 `{ "error": "Unknown device." }`.
  4. `POST readings?on_conflict=device_id,ts` with `prefer: resolution=ignore-duplicates,return=minimal`, each row raw + `soil_pct`, `water_left_ml`, `battery_pct`.
  5. `POST device_events?on_conflict=device_id,ts,type` likewise; `watered` rows get `ml = wateredMl(pump_ms)`.
  6. If `acked` non-empty: `PATCH device_commands?device_id=eq.<id>&id=in.(…)&acked_at=is.null` `{ acked_at }`.
  7. Newest valid reading (max `ts`): only if newer than the row's `reading_ts` (or that is null), its converted values become the row's latest (`reading_ts`, `soil_pct`, `water_left_ml`, `float_low`, `battery_pct`, `charging`).
  8. `instructions = instructionsFor(cal, latest battery_pct)`.
  9. `PATCH devices?id=eq.<id>` with `last_seen_at = now`, `firmware_version`, `fault_code = fault`, `sync_interval_s = instructions.sync_interval_s`, plus step 7's values.
  10. `GET device_commands?device_id=eq.<id>&acked_at=is.null&order=created_at&select=id,type` → `commands`.
  11. 200 `{ instructions, commands }`. Any throw → 500 "Something went wrong.". Log `{ fn: 'device-sync', requestId, deviceId, outcome, skipped }`.
